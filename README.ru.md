# 🗺️ netbox-schematic

**Визуальный конструктор стоек, кабельных трасс, питания и адресного пространства для [NetBox](https://netbox.dev).**

Серверные, стойки, устройства, порты и кабели — на одной интерактивной 2D-схеме.
Смотри, как сигнал идёт от ПК через патч-панели до core-коммутатора, и строй
инфраструктуру **кликами**, а не формами и таблицами.

Схема **нигде не хранится** — всегда вычисляется из живых данных NetBox (устройства,
кабели, префиксы). Нет второго источника правды, нечему рассинхронизироваться.
Весь фронтенд — чистые DOM + SVG + `fetch`: **без зависимостей и без шага сборки.**

## ✨ Текущая версия — `0.69.6`

Всё ниже работает уже сейчас. Проект до 1.0 и быстро развивается.

**Схема и трассировка**
- Устройства — карточками, порты — точками (**front/rear** патч-панелей раздельно),
  кабели — цветными линиями без пересечений, разводка круглая или угловая (Манхэттен).
- **Трассировка** — клик по занятому порту подсвечивает весь путь сигнала насквозь
  **через патч-панели** (с учётом модели `PortMapping` front↔rear в NetBox 4.6).
- Слои, фильтры по семействам, радио-линки и circuit-провайдеры.

**Режим стройки** (тумблер 👁 / ✏️ в шапке)
- Создание площадок, серверных, стоек, устройств (кликом по юниту), кабелей (кликом
  по двум портам), сетей и IP-адресов — всё пишется прямо в NetBox.
- Дерево **группа мест → площадка → серверная → стойка** с drag-and-drop: перенос
  узлов между родителями как папок, мультивыбор одного уровня, переименование, удаление.
  В NetBox есть ещё *регионы*, но регион и группа мест — две **независимые** оси (ни
  одна не вкладывается в другую), поэтому смешивать их в одном дереве неоднозначно.
  Плагин использует **группу мест** для орг-иерархии (она вложенная: кампус → офис →
  филиал); регион площадки, если задан, — просто метка, не уровень дерева.

**Каталог устройств** (⊞ в шапке)
- Просмотр типов устройств и **превью, как каждый ложится нодой** (физический +
  беспроводной вид рядом) ещё до размещения.
- Для своих моделей (производитель «Схематика») правка **стоковых портов** — ряды
  вид + тип + количество — пишутся шаблонами компонентов на тип.
- **Применить ко всем** устройствам типа или **↦ по роли**: назначить модель всем
  устройствам роли и **привести** порты — добавить недостающие, убрать свободные лишние,
  занятые (с кабелем) не трогать.

**📱 Планшет и телефон**
- Сайдбар — выезжающий drawer; детали и стойки — шторки снизу (закрываются свайпом);
  пинч-зум и панорамирование полотна одним пальцем.
- **Трасса-обозреватель** — тап по устройству грузит **только его** с тающими
  «волосками» на занятых портах; тап по порту подтягивает соседа **полной нодой** с
  реальными кабелями — и так шаг за шагом идёшь по топологии.
- **Работа с деревом без мыши**: кнопка «**Выбрать**» — мультивыбор одного уровня и
  **Переместить** (тап по месту → «← сюда?» → «Применить»); «**+**» на схеме открывает
  каталог создания устройств.

**Импорт / экспорт Excel** (форма «Patchen/Umpatchen»)
- **Импорт**: перетащи `.xlsx` в модалку → превью («будет создано: N розеток,
  панелей, свичей, кабелей») → подтверждение. Каждая строка превращается в
  настоящие объекты с настоящей коммутацией: розетка → front патч-панели,
  маппинг rear → порт свича — импортированный путь трассируется насквозь.
  Площадку можно выбрать или создать на месте; локацию — принудительно задать
  одну. Идемпотентно: повторный импорт того же файла ничего не дублирует.
- **Экспорт**: иерархическое дерево выбора (группы → площадки → локации →
  стойки → устройства) с каскадной отметкой. Строка выгружается от каждого
  **конечного устройства** (ПК, камера, сервер, розетка…) с трассой через
  розетку и/или панель до свича; выбор одного свича выгружает всё, что на него
  скоммутировано (обратная трасса). Розеточные строки round-trip: импортируются
  обратно 1:1.

**Быстрая загрузка на слабых серверах**
- Весь scope (устройства + порты + кабели + IP) отдаёт **один эндпоинт плагина**
  с компактной сериализацией вместо ~40 generic-REST-запросов — большие локации
  вместо минут открываются за секунды даже на 2 gunicorn-воркерах.
- Длинные списки id бьются на пачки (нет HTTP 414), пагинация живёт за прокси и
  на нестандартных портах, кабели тянутся один раз (без двойной сериализации).

**Готовые устройства** — каталог в один клик (ПК, свич, роутер, камера, PDU,
патч-панель, розетки, контроллеры…), заводящий `DeviceType` по требованию.
Розетки смоделированы как мини-патч-панели (пары front/rear) — трасса проходит
и сквозь них. См. ниже.

&nbsp;&nbsp;`▹` Холст «Виртуализация» &nbsp;→&nbsp; холст «Туннели / VPN»
&nbsp;&nbsp;`▹` Выбор модели при создании &nbsp;·&nbsp; локализация · подсказки · права &nbsp;·&nbsp; диапазон версий NetBox

По приоритету:

1. **Сетевые сущности** — начать с оси **VLAN** (разблокирует Виртуализацию / Туннели /
   слои), затем IP Range, Aggregate·RIR, Role, FHRP.
2. **Универсальный маппинг полей импорта/экспорта** — колонки по названиям
   (с синонимами), а не по фиксированным позициям.
3. **Выбор модели устройства** — опционально указать реальную вендорскую модель при
   создании (напр. принтер *Canon*), поверх быстрого каталога готовых решений.
4. Холст **«Виртуализация»**, затем **«Туннели»** (начать наложением на Инфраструктуру).
5. **Платформенное** — локализация, подсказки, обработка прав (403 → только просмотр).
6. **Диапазон версий NetBox** — нижняя граница **4.5+** (через `min_version`; см.
   [Совместимость с NetBox](#-совместимость-с-netbox)). Каждый новый релиз NetBox
   перепроверяется `tests/check_compat.py`, потолок «протестировано» поднимается;
   шимы под старые версии — точечно по запросу, не проактивно.

## 📦 Установка

Требуется **NetBox 4.6** (Django 6, Python 3.12) — версия, под которую плагин
разрабатывается и тестируется. Для полной работы нужен **4.5 или новее** — см.
[Совместимость с NetBox](#-совместимость-с-netbox) ниже.

```bash
# в venv самого NetBox (напр. `source /opt/netbox/venv/bin/activate`):
git clone https://github.com/TSDavid135/netbox-schematic.git
cd netbox-schematic
pip install .             # собрать и поставить плагин в этот venv
```

Включи в `configuration.py`:

```python
PLUGINS = ['netbox_schematic']
```

Собери статику плагина и перезапусти NetBox:

```bash
python manage.py collectstatic --no-input
```

В меню появится пункт **Plugins → Схематика** (`/plugins/schematic/`). **Миграции БД не
нужны** — плагин ничего своего не хранит (схема всегда вычисляется из живых данных
NetBox). Аутентификация — обычная сессия NetBox; токены и CORS не нужны.

## 🔗 Совместимость с NetBox

Таргет — **NetBox 4.6**; для полной работы нужен **4.5 или новее**. Плагин завязан на
изменения моделей, которые появились в конкретных релизах NetBox (даты — по истории
миграций самого NetBox: `0071_prefix_scope` в 4.2, `0222_port_mappings` в 4.5):

| Модель NetBox, что использует плагин | Появилась в | Нужна для |
|--------------------------------------|:-----------:|-----------|
| `Device.role` (был `device_role`) | 3.6 | — *(авто-детект; работает с любым именем)* |
| приложение `vpn` (туннели / L2VPN) | 3.7 | холст «Туннели / VPN» |
| `Prefix.scope` (был `.site` FK) | 4.2 | холст «Сети / IPAM» |
| **`PortMapping`** (модель front↔rear) | **4.5** | **импорт / экспорт Excel + трасса front↔rear** |

Что реально работает по версиям NetBox:

| NetBox | Статус | Что отваливается ниже |
|--------|--------|-----------------------|
| **4.5 – 4.6** | ✅ **Полностью** | — *(разработка и тесты на 4.6.4)* |
| 4.2 – 4.4 | ⚠️ Частично | **импорт/экспорт Excel** (нет `PortMapping`) |
| 3.7 – 4.1 | ⚠️ Частично | + **Сети / IPAM** (у `Prefix` старый `.site` FK, а не `scope`) |
| < 3.7 | ❌ Не поддерживается | + холст **«Туннели»** (нет приложения `vpn`) |

> **Проверь свой NetBox:** `tests/check_compat.py` интроспектирует живые модели и
> эндпоинты и печатает `OK`/`FAIL` по каждому допущению выше — гоняй перед
> установкой на незнакомую версию.

## 🧪 Тестирование

Разработка ведётся на локальном NetBox 4.6 (Windows + PostgreSQL/Redis в докере),
нагрузочное тестирование — на **заведомо слабом VPS**: 1 vCPU × 2000 МГц, 1,5 ГБ RAM,
Ubuntu 24.04, bare-metal NetBox с 2 gunicorn-воркерами — чтобы найти, где плотная
локация начинает лагать.

**Локальная нагрузка — одна локация, растущее число нод.** Весь scope (устройства +
порты + кабели + IP) отдаёт **один** эндпоинт (`/plugins/schematic/graph/`, компактно,
без N+1), а не ~40 generic-REST-запросов — поэтому даже большая локация открывается за
секунды на одном ядре. Платформо-независимый предиктор плавности — сколько
DOM/SVG-элементов рисует полотно (ноды + кабели + портовые точки):

| Плотность (одна локация) | Нод | Элементов полотна | Результат |
|--------------------------|:---:|:-----------------:|-----------|
| 3 стойки  | 30  | ~250   | мгновенно |
| 6 стоек   | 78  | ~690   | мгновенно |
| 12 стоек  | 228 | ~2 100 | лёгкая задержка первого рендера, дальше плавно |
| 24 стойки | 648 | ~6 100 | тяжело — пан/зум лагает |

Реальная локация обычно 2–6 стоек (мгновенно); 648 устройств в *одной* локации —
стресс-экстремум ради поиска потолка.

**Планируемая оптимизация** (после релиза — бьёт только по очень плотным локациям):
1. **LOD по зуму** — на общем плане прятать портовые точки и подписи, кабели рисовать
   прямыми (портовые точки — ~⅔ всех элементов; дёшево и даёт больше всего);
2. **кластеризация стоек** — свернуть стойку в один блок со счётчиком «пучка» кабелей,
   разворот по клику;
3. **виртуализация вьюпорта** — рисовать только то, что на экране.

Также проверяется: геометрия/раскладка Node-харнессами на реальных модулях (раскладка
без пересечений, разводка проводов, классификация семейств кабелей); импортёр/экспортёр
round-trip-тестами (импорт → экспорт → повторный импорт = 1:1); и проверки в
[`tests/`](tests/).

## 🧰 Готовые устройства

Кроме добавления устройств любого существующего типа NetBox, плагин везёт каталог
**готовых решений** в один клик — из палитры, меню «Добавить» в дереве или (на мобиле)
кнопкой «**+**» на схеме. По сути решение заводит удобную **роль** (с иконкой и портами
по умолчанию) и **не привязывает к модели**:

- **Модель всё равно выбираешь ты.** Решение по требованию создаёт generic-`DeviceType`
  под производителем **«Схематика»**, но устройство можно указать на **реальную
  вендорскую модель** (напр. принтер *Canon*) из любой импортированной библиотеки типов
  — роль при этом сохраняется.
- **Точное число портов при создании.** Добавляя устройство, можно задать, сколько у
  него сетевых портов, и плагин создаст ровно столько интерфейсов — не нужно заранее
  описывать полный шаблон типа.

Встроенный каталог:

- **Потребители** — ПК, ноутбук, принтер, IP-камера, ТВ, IP-телефон, ЧПУ, POS, датчик.
- **Сетевое** — роутер, свич, точка доступа, файрвол, медиаконвертер, патч-панель,
  провайдер (WAN).
- **Питание** — PDU, ИБП, стабилизатор, распределительный щит. · **Стойки.**

Каталог — в `static/netbox_schematic/js/solutions.js`, правится без кода (подписи,
иконки, роли, цвета, число портов по умолчанию).

## 🔌 Библиотеки устройств из других репозиториев

Плагин рисует **любое** устройство, уже заведённое в NetBox — встроенный каталог лишь
для удобства. Для реальных вендорских моделей импортируй внешнюю библиотеку типов:

- **[netbox-community/devicetype-library](https://github.com/netbox-community/devicetype-library)**
  — большая коллекция определений `DeviceType` (YAML) под реальное железо.
- Импорт по одному через штатный импорт типов NetBox или массово —
  **[netbox-community/Device-Type-Library-Import](https://github.com/netbox-community/Device-Type-Library-Import)**.

Иконки подбираются автоматически по роли / имени / модели устройства
(`iconForDevice()` в `solutions.js`), так что импортированные устройства сразу с иконками.

## 🗂️ Структура репозитория

```text
netbox-schematic/
├── README.md                     — версия EN
├── README.ru.md                  — этот файл (RU)
├── LICENSE                       — MIT
├── pyproject.toml                — пакет плагина
└── netbox_schematic/             — плагин NetBox
    ├── __init__.py               — PluginConfig
    ├── navigation.py             — пункт меню
    ├── views.py                  — страницы + эндпоинты: graph (быстрый scope), импорт, экспорт
    ├── importer.py               — парсер Excel «Patchen/Umpatchen» → устройства + кабели
    ├── exporter.py               — обратное: связи scope → та же Excel-форма
    ├── urls.py
    ├── templates/netbox_schematic/
    │   └── schematic.html        — тонкая оболочка: {% static %} + {% csrf_token %}
    └── static/netbox_schematic/  — клиентская логика (JS-модули) и стили (CSS)
```

Технологии: чистые DOM + SVG + `fetch`, без шага сборки; единственная бэкенд-зависимость
— `openpyxl` (импорт/экспорт Excel). Аутентификация — сессия NetBox + CSRF
(`X-CSRFToken` из скрытой формы).

## 🛠️ Разработка

Плагин ставится editable (`pip install -e .`); правки шаблона подхватываются dev-сервером
сразу. После изменений в `static/` — `manage.py collectstatic` (или обновление с
отключённым кэшем — при `DEBUG=True` dev-сервер отдаёт статику плагина напрямую).
Геометрию/раскладку проверяем маленькими Node-харнессами на реальных модулях.
