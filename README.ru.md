# netbox-schematic

[English](README.md) · **Русский**

Визуальный конструктор стоек и кабельных трасс для [NetBox](https://netbox.dev):
серверные, стойки, устройства, порты и кабели — на одной интерактивной
2D-схеме. Смотри, как сигнал проходит от сервера через патч-панели до
core-коммутатора, и строй инфраструктуру кликами — без форм и таблиц.

## Возможности

- Дерево «регион → площадка → серверная → стойка» с drag-and-drop
  (перетаскивание узлов между родителями, как папки в ОС) и стойки с юнитами.
- 2D-схема: устройства прямоугольниками, порты точками (front/rear
  патч-панелей раздельно), кабели линиями без пересечений.
- Трассировка: клик по занятому порту подсвечивает весь путь сигнала
  насквозь через патч-панели.
- Режим стройки: создание площадок, серверных, стоек, устройств (кликом
  по юниту), кабелей (кликом по двум портам), сетей и IP-адресов.
- Панорамирование полотна, кастомные тултипы, демо-анимация трафика.
- Схема нигде не хранится — всегда вычисляется из данных NetBox.

## Холсты

В плагине четыре холста (переключение — в сайдбаре):

- **Инфраструктура** — стойки, устройства, порты, кабели, питание. *Готов.*
- **Сети / IPAM** — адресное пространство: префиксы, привязанные к местам
  (регион/площадка/серверная) через `scope` NetBox, занятые и свободные IP. *Готов.*
- **Виртуализация** — кластеры, ВМ, VM-интерфейсы, VLAN-шина. *В планах.*
- **Туннели / VPN** — туннели / L2VPN оверлеем поверх интерфейсов. *В планах.*

## Установка (плагин)

Требования: **NetBox 4.6** (Django 6, Python 3.12) — версия, на которой плагин
разрабатывается и тестируется. Использует актуальные REST-модели NetBox
(`Prefix.scope`, приложение `vpn`, модель маппинга front↔rear `PortMapping`),
поэтому на более старых 4.x возможны отличия. Поддержка диапазона версий
(определять версию NetBox и адаптироваться, либо объявить поддерживаемый диапазон)
— в планах.

```bash
pip install -e .          # из корня этого репозитория, в venv NetBox
```

В `configuration.py`:

```python
PLUGINS = ['netbox_schematic']
```

Перезапусти NetBox — в меню появится **Plugins → Схематика**
(`/plugins/schematic/`). Аутентификация — обычная сессия NetBox,
токены и CORS не нужны.

## Готовые устройства

Кроме добавления устройств из любого существующего типа NetBox, плагин несёт
встроенный каталог **готовых решений** — добавляются в один клик из палитры или
меню «Добавить» в дереве, без выбора типа устройства. Каждое решение создаёт (при
необходимости) `DeviceType` под производителем **«Схематика»** с ролью, иконкой и
числом сетевых / силовых портов по умолчанию:

- **Потребители** — ПК, ноутбук, принтер, IP-камера, ТВ, IP-телефон, станок с ЧПУ,
  POS-терминал, датчик, прочее оборудование.
- **Сетевое** — роутер, коммутатор, точка доступа, межсетевой экран, медиаконвертер,
  патч-панель, провайдер (WAN).
- **Силовое** — PDU, ИБП, стабилизатор напряжения, распредщиток.
- **Стойки.**

Каталог — в `static/netbox_schematic/js/solutions.js`, правится без изменения логики
(подписи, иконки, роли, цвета, число портов по умолчанию).

## Демо-данные

`demo_seed.py` (корень репозитория) наполняет NetBox полным справочником решений и
демо-топологией (группа «Кампус → Головной офис» с двумя серверными, подгруппа
«Филиалы → Филиал Юг», стойки, кабели, питание, off-rack-устройства и IPAM).
Идемпотентен. Запуск на своём NetBox (НЕ через `manage.py shell`):

```bash
source /opt/netbox/venv/bin/activate
cd /opt/netbox/netbox
python /путь/к/demo_seed.py
```

## Устройства из сторонних репозиториев

Плагин рисует **любое** устройство, уже заведённое в NetBox — встроенный каталог
лишь для удобства. Чтобы использовать реальные модели вендоров, импортируй внешнюю
библиотеку типов устройств:

- **[netbox-community/devicetype-library](https://github.com/netbox-community/devicetype-library)**
  — большая community-коллекция определений `DeviceType` (YAML) для реального железа.
- Импорт — либо по одному через импорт типов устройств в NetBox (вставка YAML/JSON),
  либо массово community-импортёром
  **[netbox-community/Device-Type-Library-Import](https://github.com/netbox-community/Device-Type-Library-Import)**
  (скрипт грузит библиотеку через REST API).

Когда типы устройств появились в NetBox, добавляй устройства этих типов (через NetBox
или плагин) — они отрисуются на схеме. Иконки подбираются автоматически по
роли / имени / модели (`iconForDevice()` в `solutions.js`), так что импортированные
устройства сразу получают осмысленные иконки.

## Структура репозитория

```text
netbox-schematic/
├── README.md                     — этот файл (EN)
├── README.ru.md                  — русская версия
├── LICENSE                       — лицензия MIT
├── pyproject.toml                — пакет плагина
├── demo_seed.py                  — идемпотентный сидер демо-данных
└── netbox_schematic/             — плагин NetBox
    ├── __init__.py               — PluginConfig
    ├── navigation.py             — пункт меню
    ├── views.py                  — вьюха (LoginRequired)
    ├── urls.py
    ├── templates/netbox_schematic/
    │   └── schematic.html        — тонкий каркас: {% static %} + {% csrf_token %}
    └── static/netbox_schematic/  — клиентская логика (JS-модули) и стили (CSS)
```

Технология: чистый DOM + SVG + `fetch`, без зависимостей и сборки.
Аутентификация — сессия NetBox + CSRF (`X-CSRFToken` из скрытой формы).

## Разработка

Плагин ставится editable (`pip install -e .`); правки шаблона
подхватываются dev-сервером сразу. После правок в `static/` запусти
`manage.py collectstatic` (или обнови с отключённым кэшем — dev-сервер
при `DEBUG=True` отдаёт статику приложений напрямую).
